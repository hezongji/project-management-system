# Intent: IM App 微信化改造 + 附件项目归档（v1.1 迭代）

- **Change-ID**: 20260829-im-app-v2
- **作者**: owner（2026-08-29 真机验收后提出）· **状态**: draft（待 owner 审校拍板）
- **来源**: ☑ 人的想法（owner 原话：软件功能太简陋，需要研究增加功能——项目选择、群成员显示、附件上传且必须关联项目、附件归纳到项目特定目录便于后期资料整理（让人知道是这个项目的即可），PC 端后续可将文件移动到对应文件夹，手机端先不做文件移动；UI 应参考手机微信的界面和基本功能）

## 问题（Why）

PM 聊天 App v1.0（WebView 壳 + /im 专页）已通过真机验收，但功能只有基础聊天，对比微信差距大：

1. 群聊看不到成员明细（仅人数），成员构成不透明
2. 移动端附件上传未真机验证，且要求「会话已关联项目」——单聊/普通群无法上传文件
3. 公司核心诉求「聊天中的资料沉淀到项目」未闭环：文件必须能挂到项目目录，后期按项目整理
4. 移动端 UI 是桌面双栏的应急改造，距离微信式的移动体验差距大

## 期望结果（What）

员工在 App 内获得微信式聊天体验：会话列表/气泡/长按操作/群成员抽屉；上传附件时**必须选择关联项目**（自动归档到该项目目录，文件卡片明示所属项目）；PC 端可把文件移动到项目内其他目录（一期可后置）。

## 成功标准

- [ ] App 聊天界面按微信范式重构：会话列表（头像/时间/未读红点）、聊天气泡、底部输入栏、+ 号面板
- [ ] 群聊标题点击可见成员列表（头像/姓名/角色），会话列表可看成员
- [ ] 移动端上传附件全流程可用（选文件→选项目→选目录→上传→消息带文件卡片）
- [ ] 附件上传强制关联项目：文件落库 projectId+目录，消息卡片显示「项目名/目录」归属
- [ ] PC 端可将文件移动到项目内其他目录（若一期不做，移动端上传的文件也能在 PC files 模块可见可管）
- [ ] 网页 /messages 桌面端零回归

## 范围

- **做**: 移动端 IM 微信化 UI、群成员显示、附件上传+项目关联（含选项目/选目录交互）、文件卡片归属展示、PC 端文件移动 API+入口
- **不做（非目标）**: 语音消息/音视频通话（二期）、表情包商店、朋友圈、手机端文件移动/重命名（owner 明确）、im-server 协议改动（除非必要）

## 约束（硬约束）

1. **不动 im-server 核心链路与 PG 表结构**（除非 spec 论证必要）；文件归档用现有 File/FileCatalog 模型（projectId 必填 + storagePath 按项目归档已天然满足）
2. **上传必须关联项目**（owner 强制）——上传流程不允许无项目状态；会话已关联项目时预选，未关联时强制选择
3. **手机端不做文件移动**（owner 明确），PC 端移动能力单独评估
4. **复用现库现协议**：不引入新的移动端框架（仍是 WebView 壳 + Next.js），新增 npm 依赖须论证
5. PM 网页 IM（/messages）零回归，共享组件改造需双端兼容

## 未决问题（S2 前需 owner 决断）

1. 项目选择范围：全部项目 vs 我参与的项目
2. 上传默认目录：项目根目录 vs 记住上次选择
3. 语音消息：一期做不做
4. 表情：一期做不做（系统 emoji 面板 vs 图片表情包）
5. PC 端文件移动：一期一起交付 vs 二期
