# Intent: IM App 深度微信化（v1.2 迭代）

- **Change-ID**: 20260829-im-app-v3
- **作者**: owner（2026-08-29 v1.1 验收反馈）· **状态**: draft（待 owner 审校拍板）
- **来源**: ☑ 人的想法（owner 原话：这个功能和微信差太多了，请参考微信再增加一些功能，UI 界面务必和手机微信一样，功能缺失的就补充进去）

## 问题（Why）

v1.1 已具备微信式骨架（会话列表/气泡/成员抽屉/+面板/emoji/长按/附件项目归档），但对照手机微信仍有明显差距：

1. **结构差距**：微信是「底部 3-4 Tab + 各页深导航」，App 现在只有单页聊天（无通讯录页、无「我的」页、无全局导航）
2. **会话列表差距**：无置顶、免打扰、删除会话、会话搜索
3. **聊天页差距**：无语音消息、无时间分隔线、无消息多选/转发/删除、无双击头像@、无群公告/@所有人、聊天背景与微信不一致
4. **细节差距**：头像样式、输入栏交互（语音切换按钮）、长按菜单样式、消息密度、下拉刷新等

## 期望结果（What）

App 的聊天核心体验达到「微信 95% 相似度」：结构（底部 Tab：聊天/通讯录/我的）、会话列表能力（置顶/免打扰/删除/搜索）、聊天能力（语音消息/多选转发删除/双击@/@所有人/群公告/时间线）、UI 细节（配色/气泡/输入栏/长按菜单/背景）。

**不做（非企业 IM 范围，明确告知 owner）**：朋友圈、红包/支付、小程序、视频号、视频通话（WebRTC 大工程，二期另议）、语音通话。

## 范围

- **做（v1.2，约 8-10 天）**: 上表 ✅ 全部
- **不做**: 朋友圈/支付/小程序/视频通话/语音通话/语音转文字（二期）、消息搜索（二期）、合并转发消息（二期）、文件预览增强（二期）

## 约束

1. 复用 v1.1 全部成果（hooks/组件/上传链路/归档）；im-mobile 目录继续扩展
2. 不动 im-server **协议与核心链路**；仅同步 schema（VOICE 枚举）+ 3 行 mentions 守卫（v4-pro 定案）
3. 语音消息：WebView MediaRecorder → POST 上传（复用 files upload 通道或独立 media 上传）→ IMAGE 类型扩展或新 VOICE 消息类型（S3 定）
4. 数据侧：置顶/免打扰/本地删除为**设备本地**（localStorage）或服务端偏好（S3 定，优先本地零改表）
5. PM 网页 IM 零回归（共享组件继续双端兼容）
6. 组织架构页 = 只读（复用 PM organization 数据接口，不做管理操作）

## 未决问题（S2 前 owner 决断）

1. 底部 Tab：三 Tab（聊天/通讯录/我的）vs 四 Tab（加「项目」页——按项目聚合会话与文件）
2. 语音消息：确认提前到 v1.2（owner 上轮拍板二期，本轮「功能缺失就补」或已推翻）
3. 置顶/免打扰/删除：设备本地（换手机丢失）vs 服务端存储（多端同步，需小迁移）——推荐服务端（员工换机不丢，成本低）
4. 群公告：只读展示 vs 可编辑（群主/管理员）——推荐可编辑（企业 IM 刚需）
5. 通讯录：只读组织架构 vs 可发起单聊的通讯录（推荐可点人发起单聊）
