# Intent: PM 系统手机移动端 UI/UX 彻底重适配

- **Change-ID**: 20260830-mobile-ui
- **作者**: owner · **状态**: draft → accepted
- **来源**: ☒ 人的想法（owner 2026-08-30：现有移动端适配太拉胯，需彻底适配手机端界面风格）

## 问题（Why）

PM 系统（pm.hezongji.cn，Next.js 16 + Tailwind + shadcn/ui）桌面端功能完整，但手机端体验差：
- 12 个主页面只有零散 `md:hidden/sm:` 断点修补，无移动优先信息架构
- 待办（0 处适配）、文件/网盘（0 处，左右树+列表双栏）在手机上基本不可用
- 项目详情/阶段/任务、采购审批等表格布局靠横向滚动硬撑，触控目标小
- 已上线 IM 独立 App（WebView 壳）四 Tab 微信式移动端方案是成功的标杆，但仅覆盖 IM，其余页面未跟进
- 根因：桌面优先开发 + 无统一移动端组件体系

## 期望结果（What）

手机端（重点 375-430px）全页面达到"像原生 App 一样好用"：
- 主导航改为**底部 Tab**（微信式，如 首页/项目/待办/我的，其余入口收抽屉），与 im-mobile 风格统一
- 列表全部卡片化、触控目标 ≥44px、安全区适配（env(safe-area-inset-*)）
- 采购审批保留完整流程，改为移动卡片流
- 桌面端布局零改动，共用同一套数据接口

## 成功标准（怎么算对）

- [ ] 375px 视口下核心链路页面**无横向滚动、无元素遮挡、无 44px 以下触控目标**

- [ ] 底部 Tab 主导航在全部主页面生效，抽屉收纳次要入口
- [ ] 桌面端回归：现有 verify/测试全绿，桌面截图走查无视觉回归
- [ ] 验收脚本：`scripts/mobile-ui-verify.mjs`（375px 断言：无横向滚动/触控尺寸/关键元素可见）
